# Head-to-head against the existing kernels

Generated by `scripts/summarize_third_party.py` from
`results/third_party_bfloat16.json`. Reproduce with `scripts/fetch_third_party.sh`
then `python bench/bench_third_party.py`.

NVIDIA RTX PRO 6000 Blackwell Max-Q Workstation Edition, bf16, median of 100 CUDA-event-timed
reps with L2 flushed between them. Every implementation is verified against a
float64 oracle before it is timed, with each project's RMSNorm gain set to ones,
logit scale to 1.0 and output RMSNorm disabled so all compute the same function.

## Batched pseudo-queries: where catswe's design wins

The paper's two-phase schedule (Sec. 4.2) amortizes one pass over the block
representations across all `S` pseudo-queries in a block. catswe implements
that; our operator has no such API, so the honest comparison is `S` separate
calls.

| approach | ms |
|---|---|
| switchyard x8 calls | 0.930 |
| catswe phase1 S=8 | 0.215 |

**catswe is 4.3x faster on this axis.** Our per-call kernel is at the
memory ceiling, but it reads the sources once *per query*; theirs reads them
once per *block*. At `S=8` that is an 8x traffic difference and no amount of
kernel tuning closes it -- it is an API and scheduling difference, and the
clearest single piece of future work this comparison surfaced.

| **switchyard** | 1.66e-03 | 1.00x |
| Liger-Kernel | 2.14e-03 | 1.29x |
| fla | 1.66e-03 | 1.00x |
| catswe | 1.66e-03 | 1.00x |

At N=9 B=1 T=4096 D=2048. switchyard, fla and catswe all sit exactly at the
floor -- they accumulate in fp32 and round once. Liger is 1.29x, which is still
fine, but it is a real difference and it grows with `N` (1.43x at `N=32`).

## A harness bug worth recording

fla takes a *sequence* of sources rather than one stacked tensor, which is how
a real model holds them: each block representation is produced by a different
layer. The first version of this benchmark handed it `N` views of a single leaf
tensor instead, which makes autograd route every gradient back through `N`
slice-backwards plus an accumulation.

| fla backward at N=9 D=2048 | ms |
|---|---|
| `N` views of one leaf (wrong) | 4.146 |
| `N` separate leaves (its actual API) | 0.956 |

A **4.3x** penalty created entirely by the harness. Reported as
published, it would have made fla look 11x slower than us at `N=9` and 29x at
`N=32`, when the true figures are 2.7x and 1.5x. Both numbers are kept in the
JSON because the gap is itself informative: it is the cost of the pointer-table
API when the sources really do live in one buffer.
